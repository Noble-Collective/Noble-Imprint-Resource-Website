# BSB Text Validation — Admin-Triggerable Integrity Check with History

**Date:** 2026-08-28
**Status:** In progress — core module built & verified; admin integration pending approval
**Branch:** `worktree-bsb-validation` (isolated git worktree, to avoid colliding with the in-flight analytics work)
**Repos touched:** `Noble-Imprint-Resource-Website` (feature). Read-only against `Noble-Imprint-Resources` content repo (except the future "Apply Latest BSB Text" phase, which writes `references.json` with explicit approval).

## Goal

Give admins a way to independently confirm that the Bible text the site serves is a faithful, complete copy of the official Berean Standard Bible — no dropped verses, no import corruption, no typo/markup drift on our side. Run on demand from the admin console; keep a history of past runs. Plus a follow-on action to sync our copy to the latest upstream in one click.

- **Proves:** our stored copy matches the official BSB master.
- **Does not prove:** the BSB *translation itself* is error-free (the committee's domain).

## External source of truth — bereanbible.com (public domain since 2023-04-30)

- **Verse text:** `https://bereanbible.com/bsb.txt` — tab-delimited `Book Ch:V<TAB>text`, 2 attribution lines + a `Verse` header row. ~31,102 verses.
- **Structure:** `https://bereanbible.com/bsb_usfm.zip` — 66 USFM files (headings, footnotes, cross-refs). NOTE: autogenerated by their `bsb2usfm` tool — a *different USFM encoding* from ours (see Check B).

Each run fetches these live and records the upstream `Last-Modified`/`ETag` so history distinguishes "our copy drifted" from "upstream published a revision."

## Our side (read via the existing github.js cached path)

- **Verse text:** `bibles/bsb/references.json` (flat `"Book Ch:V" → text`).
- **Structure:** `bibles/bsb/content/*.SFM` (66 files, `01GENBSB.SFM` naming).

## The two checks

### Check A — Verse text (`references.json` vs `bsb.txt`)
Exact pass + normalized pass (NFC, curly→straight quotes, dash/space/zero-width folding). Reports `missingInOurs`, `extraInOurs`, `textMismatch` (real), `cosmeticOnly`.

### Check B — SEMANTIC structure (headings + footnotes)
**Important redesign:** a raw line-diff of our USFM vs the official zip is meaningless — they're two different USFM encodings of the same text (~90k lines of markup-convention noise). Instead we **extract the semantic apparatus the sites consume** and compare per book:
- **Section headings** (`\s1`/`\s2`) — rendered by this reader (bible.js).
- **Footnotes** (`\f … \f*`, prose only) — consumed by the Coram Deo / Catena study app.

Encoding artifacts normalized away so only real content differences surface:
- filename styles reconciled to a canonical book code (`01GENBSB.SFM` ↔ `bsb_usfm/GEN.usfm`).
- footnote `\ref display|target\ref*` markup reduced to display text (ours stores plain text).
- space-before-punctuation left by `\ref*` stripping removed.
- CRLF vs LF, inline char markers (`\nd` etc.), whitespace.

Cross-references (`\x`/`\r`) are a possible future add; footnotes cover the study-app need for now.

### Status
`pass` = no real verse diffs AND no heading/footnote/book diffs (cosmetic verse diffs allowed). `fail` = real diffs. `error` = fetch/parse failure.

## Architecture (fits existing conventions)

### Server
- **`src/server/bible-validation.js`** — PURE, dependency-free core (Node built-ins only; own `zlib`-based ZIP reader so it unit-tests without node_modules). Exports: `parseBsbTxt`, `parseReferences`, `normalizeVerse`, `diffVerses`, `parseZip`, `bookCode`, `extractHeadings`, `extractFootnotes`, `diffStructure`, `overallStatus`, … ✅ **BUILT + 16 unit tests passing + verified against live data.**
- **Endpoints in `admin-routes.js`** (auto-guarded by `requireAdmin`), synchronous like `/diff-report`:
  - `POST /api/admin/bible-validation/run` — fetch upstream + read our files via github.js + run both checks → write summary to Firestore → return result.
  - `GET /api/admin/bible-validation/runs` — `orderBy('startedAt','desc').limit(25)`.

Sync run (~10–30s) — within Cloud Run's timeout; no new job infra.

### Persistence — Firestore `bibleValidationRuns`
Cloud Run FS is ephemeral; content-repo writes fire `notify-website`. Firestore avoids both. Doc: `{ translationId, startedAt, finishedAt, durationMs, runBy, upstream:{bsbTxt,usfmZip versions}, status, verseCheck:{totals, examples≤25}, structureCheck:{totals, examples≤25}, truncated }`. Examples capped for the 1 MB doc limit.

**Citation-anchored quotation audit (Phase 5, per Steve):** `src/server/bible-citations.js` reuses parser.js's citation grammar (book list + ref regexes, copied with a keep-in-sync note) to walk every `(Book C:V)` citation and the `<<`/blockquote attribution form. For any citation of a *changed* verse, it extracts the adjacent quoted passage and diffs it against the verse (`classifyQuote`): `current` (matches new → skip), `stale` (matches old → offers a verbatim auto-fix when encoding matches, else flags manual), `divergent` (paraphrase/other → review). Surfaced as a "Cited quotations to review" list in the admin UI. Proven on real content: **3,849 citations / 2,308 distinct verses / 561 with adjacent quotes** extracted correctly. Complements the span search (which catches uncited quotes); the two run in the same file pass. `computeChangeAnchor` moved to `bible-validation.js` to keep both consumers dependency-clean (no circular require). Note: a full "audit ALL citations vs the current Bible" (not just changed verses) is now a small extension but needs fuzzy-match tuning to filter paraphrase/partial/non-English quotes — deferred.

**UI status label:** a run with differences shows **"Diffs Detected"** in amber (`admin-badge--warn`), not a red "FAIL" — since our copy will usually be slightly behind upstream. Internal status value stays `fail` for history consistency; only the display label/colour changed. Added CSS (`admin-badge--ok/warn/err`, `admin-card`, `.bv-change ins/del`) + bumped `style.css?v=87`.

## Quotation Audit enhancements (2026-09-01, shipped)

The audit graduated from a "changed-verse only" check to a standing full-library audit, with the "Fix quote" flow reworked from repeated real-world review. Deployed to production.

- **Aligned fragment, not the whole verse** — `correctQuote` (`bible-quote-audit.js`) aligns the quote to the verse by word-LCS on **bare (punctuation-stripped)** words, narrowed to the most **compact** window that still yields the full LCS. This anchors a repeated quote word to the nearest occurrence (Genesis 37:24 "a pit" no longer spreads to the verse's second "pit"), tolerates boundary substitutions ("came"→"come"), and trims clauses the quote never covered (John 1:9). Falls back to the full verse only when it can't align.
- **Formatting-preserving Fix** — `peelRaw(raw, peelQuotes)` splits the wrapper markup from the scripture core; `computeFix` returns `{span}` (plain, for highlighting) + `{replacement}` (the exact source text to write: the corrected span re-wrapped in the quote's own markdown). Blockquote `>`, italics/bold and quote marks are preserved. `peelRaw` is **kind-aware** — quote marks are peeled only for inline quotes; a trailing `"` in a blockquote is scripture (Jesus's speech) and is kept, fixing a `.”.”` / `."."` double-tail bug (Matt 28:20, Matt 19:13). The inline `raw` (in `bible-citations.js`) now spans **both** quotation marks so the box shows the complete `"…"` unit.
- **Punctuation fidelity** — the span keeps the quote's own trailing punctuation; a sentence-ending period is dropped when the quote stopped mid-sentence (Genesis 40:23 "…forgot him"), and kept when it didn't.
- **Positional highlighting** — `wordMatchFlags` + `markDiffWords` (`admin.js`) mark ONLY the words that actually differ (word-LCS), replacing the old set-membership approach that lit up every occurrence of a differing word (e.g. every "the" in Matt 19:13).
- **Colour scheme** — in-session quote light yellow with differing words darker yellow (`.qa-q`/`.qa-diff`); BSB span light green with differing (correct) words darker green (`.qa-bsb`/`.qa-diff-bsb`).
- **In-context, auto-sizing Fix box** — the editable `<textarea>` is shown inside the session's surrounding text (muted before/after, split at `f.fix.oldRaw`) so the reviewer sees how the page will read; it sizes to its content and auto-grows on edit.
- **Ordering** — findings are sorted by **reading position** (session order via an `orderByPath` tree index, then `cite.index`), not by coverage (which looked random).
- **"Show in book ↗" link** — opens the rendered session page and scrolls to/highlights the quote via a native `#:~:text=start,end` text-fragment (reuses live rendering, no duplicated book renderer; keeps editorial `[..]` brackets, strips markdown emphasis; Chromium/Edge, best-effort). Shares one link style with "Show scripture".

Cache-busters at time of shipping: `admin.js?v=36`, `style.css?v=107`. Unit tests: **125 pass** (`bible-quote-audit.test.js` covers correctQuote alignment/punctuation, peelRaw kind-awareness, and computeFix wrapper preservation incl. the Matt-28 double-quote case).
